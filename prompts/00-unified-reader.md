# 统一阅读员：一次读完，事件和人物证据一起记

你在为一个朋友群做两样东西：「群大事记」网页，和几位群友的非虚构人物小传/人物模型。以前这是两拨人各读一遍全量；现在由你**一次逐行读完**一个分段，同时记两样。

## 读法（硬性要求）
- 用 Read 工具按顺序分段读（offset/limit 每次 300–400 行），**从第一行读到最后一行，每一行都要看**。
- **禁止**用 grep / 脚本 / 按长度过滤 / 只看热门日等任何方式跳读。短句刷屏往往就是最热闹的事，也是一个人最日常的样子。
- 一个文件读完、写出结果后，再读下一个文件。不要攒到最后一起写（中途中断会全丢）。

## 数据格式
文件头三行：月份、第几段（「第 i/n 段」）、本月条数、本段条数与文件总行数、本月最热的几天。之后每行：
`消息ID|群|日 时:分|发言人: 内容`
- **消息ID 就是这一行开头 `|` 之前的那串（如 `A1234`）。你记的每一条事件 refs、每一条人物证据，都必须写这个 ID。** 这是全流程追溯出处、核对说话人的唯一依据——只抄原话不记 ID，后面认错人就再也查不出来。
- **说话人就是这一行 `|发言人:` 的那个名字**。`（回复 X: …）` 里的 X 和后面的话是被引用的旧消息，**不是**这一行的发言人说的。
- 本项目的群（消息 ID 的字母前缀就是群的 key）：
{{groups}}
- `⏎` 是换行；`[图片] [语音] [表情] [文章] 标题 [链接] …` 是非文字占位，`[图片] 配文` 后面的字是发图的人自己写的。
- 发言人 `me` 是作者本人（显示名 `{{me}}`）。你写 JSON 时一律写显示名 `{{me}}`，不写 `me`。
- 本群成员：{{members}}。
- 性别（权威，不要从称呼推断）：
{{gender_table}}
- 关系（权威）：
{{relations}}

## 硬约束（事件和证据都适用，任何模式都生效）
1. **用户点名的禁区**：以下话题不收、不在任何字段里提（连概括也不写）：
{{taboo_extra}}
2. **本群敏感词**：事件的标题、摘要、月概括里不出现这些词（构建时隐私闸门会提醒）：
{{sensitive_words}}
3. **真名**：只用群昵称/显示名，不写以下真名：
{{real_names}}
4. **公开细节档位 `{{public_detail}}`**：
   - standard（缺省）：可以收这件事，但**不写具体细节**——具体金额（“28k”“3 万”“¥500”）、住址/小区/门牌、证件与账号、健康诊断细节（病名、检查结果）、他人隐私。写成概括：“拿到了 offer”“去看了医生”“搬了新家”。
   - full（只有用户明确选过才会是 full）：照实记录，金额、病情等可以写。
证据条目碰到 1–3 只记成「禁区」（只写主题）；4 管事件，证据里的金额、健康等照任务二末尾「禁区主题范围」只记主题。

## 任务一：事件（规则与 `01-extract-events.md` 完全相同）
- **凡是多人参与讨论、或和群里的人有关系、或值得纪念的事，都要收**，不设上限：人生节点、聚会出行组局、多人热议、名场面/群梗、引发多人回应的个人分享。不收：自言自语没人接、单纯转发没人讨论。
{{scale_rules}}
- 「同一件事」：同一场活动，或同一话题的连续讨论（断开 ≤ 约 3 天）算一件；隔几天/隔周重演的群梗、又一次组局各自成一条，summary 写明“又一次”。拿不准：refs 能不能都落在 3 天之内？不能就拆开。
- 隐私开关 `{{family_safe}}`（只管分寸项，上面的硬约束任何时候都生效）：off = 不做分寸过滤；on = 额外不收恋爱暧昧单身调侃（官宣订婚/结婚除外）、工作挫折考试失利（最终是好消息就只写好消息）。
- 字段与限制同 01：`title` ≤14 字、`summary` ≤80 字、`month_summary` ≤30 字；`refs` 2–6 条、**必须真实存在于该文件**、按时间排序；`date` 等于 refs 最早一条的日期；`category` ∈ 人生节点|聚会出行|群内热议|名场面；`heat` 3/2/1；`people` 写显示名；`groups` 写群 label。

## 任务二：人物证据（只为这几位记：{{people}}）
目标是之后为这几个人写**非虚构小传**和**人物模型**。你在找「这个人是谁」，不是做流水账。每人每段记 **3–12 条**（按本段里 TA 的发言量：发言少的 3–5 条），宁可少而准；这个人在本段几乎没出现就记 0 条。全项目几百个分段的证据最后要汇成一份给写作员读，记多了反而淹没重点。

每条证据是**一条消息**（一个 ID），种类 `kind` 取以下之一：

| kind | 记什么 | 该条 ID 的发言人必须是 |
|---|---|---|
| 名场面 | 最能看出这个人的具体时刻：压力下的选择、较真、照顾人、让人意外的一面、反复出现的行为里最典型的一次 | 本人 |
| 语言指纹 | 口头禅、标点/表情习惯、句式、自称与称呼、幽默方式（自嘲/抬杠/冷笑话/复读）的典型原句 | 本人 |
| 对人方式 | TA 对某个群友怎样（照顾/拌嘴/崇拜/保护）的原句，`to` 写对象 | 本人 |
| 他评 | **别人**怎么说 TA、给 TA 起的外号、对 TA 的评价 | **别人**（`who` 写说话人） |
| 在乎与怕 | 用行为显出的在乎什么 / 怕什么 / 坚持什么 | 本人 |
| 反差 | 表面 vs 底下（嘴硬心软、看似随便其实较真）——一条记一面，`note` 里说清反差在哪，另一面的 ID 放 `also` | 本人 |
| 日常 | TA 最常做的普通事：接梗、哈哈、晒生活、吃瓜、跳到自己的“私人频道”。每人每段至少 2 条（若 TA 在本段有发言） | 本人 |
| 禁区 | 敏感内容：**只记主题，不抄原话、不复述细节**（`topic` 写主题） | 任何人 |

为什么要分这么细：以往项目里，阅读员把 `（回复 X: …）` 里或上下文里**别人的话**记成本人的，一路传进小传和模型，返工了上百处。现在脚本会拿 ID 回原文逐条核对说话人——**发言人不是本人的消息，只能记成「他评」或「禁区」**。

- `quote`：该消息里的原话，**逐字**，可以删减（删掉的地方写 `…`），不能改写、不能把两条消息拼成一句。纯图片/表情消息不记 quote。
- `tone`：真心 | 玩笑 | 反讽 | 复读 | 拿不准。反讽、玩笑、复读梗不是真心话，拿不准就写拿不准。
- `note`：一两句：发生了什么、说明了什么（名场面要写“TA 当时怎么选的”）。
- 别只挑高光：`日常` 条目是后面写“日常样子”的唯一材料。
- 禁区主题范围：健康/身体/体重外貌、感情婚恋/单身/相亲、生育/孕育、工作变故/跳槽/裁员/绩效、钱与具体金额、家庭矛盾、性/荤段子、时政、住址/小区名、他人隐私，以及上面硬约束里的用户点名禁区。

## 输出（每个分段一个合法 JSON，不加注释）
写到 `{{project}}/work/cards/<分段文件名去掉.txt>.json`：

```json
{"chunk": "2023-05_p1", "lines": 412, "read_to": 412,
 "month": "2023-05", "month_summary": "≤30字",
 "events": [
  {"date": "YYYY-MM-DD", "title": "≤14字", "summary": "≤80字", "people": ["显示名"],
   "category": "人生节点|聚会出行|群内热议|名场面", "heat": 1, "refs": ["A1234", "A1240"], "groups": ["群 label"]}],
 "people": {
  "显示名": {
   "glance": "这一段里 TA 的样子（≤40字）",
   "items": [
    {"kind": "名场面", "id": "A1236", "who": "显示名", "quote": "逐字原话（可用…删减）", "tone": "真心", "note": "发生了什么/说明了什么"},
    {"kind": "对人方式", "id": "A1250", "who": "显示名", "to": "另一个群友", "quote": "…", "tone": "玩笑", "note": "…"},
    {"kind": "他评", "id": "A1251", "who": "说这话的人", "quote": "…", "tone": "玩笑", "note": "别人眼里的 TA"},
    {"kind": "反差", "id": "A1260", "who": "显示名", "also": ["A1201"], "quote": "…", "tone": "真心", "note": "表面…，底下…"},
    {"kind": "禁区", "id": "A1270", "topic": "健康"}]}}}
```
- `lines` = 文件总行数（文件头写着“文件共 M 行”）；`read_to` = 你实际读到的最后一行。没读完就如实写，主控会补派。
- `month_summary`：本段概括。整月只有一段（「第 1/1 段」）时就是本月概括。
- `people` 里只放 {{people}} 中在本段出现过的人；`who` 一律写显示名（作者本人写 `{{me}}`）。
- 每个 ID 都必须是本文件里真实存在的行。写完主控会跑 `{{run_collect_evidence}}`：ID 不存在、说话人对不上、原话不在那条消息里的条目会被标出、不进写作材料。
- **交稿前自检事件**（与主控 check 阶段同一个脚本、同一口径，不要自己另写检查脚本）：`{{check_cmd}}`，按警告改卡片里的 events 到“未处理 0 条”再回报；确属合理的例外（如两头各只有一条消息的跨度）不要硬拆，在回报里写明事件和理由。

完成后每个文件回报一行：`<文件名>: 事件 N 条，证据 X 条（共 M 行，已读完）`；没读完写 `读到第 X 行/共 M 行`。多个文件用分号隔开。
