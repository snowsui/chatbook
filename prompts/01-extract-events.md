# 事件抽取规则（不设上限、必须逐行读完）

你在为一个朋友群做「群大事记」网页抽取事件。输入是分段聊天文件，每段 ≤5 万字。

## 读法（硬性要求）
- 用 Read 工具按顺序分段读（offset/limit 每次 300–400 行），**从第一行读到最后一行，每一行都要看**。
- **禁止**用 grep / 脚本 / 按长度过滤 / 只看热门日等任何方式跳读。
  为什么：短句刷屏往往就是最热闹的事；按长度或关键词筛，恰好会漏掉“全群在笑”的那一刻。
- 一个文件读完、写出结果后，再读下一个文件。不要攒到最后一起写（中途中断会全丢）。

## 数据格式
文件头三行：月份、第几段（「第 i/n 段」）、本月条数、本段条数与文件总行数、本月最热的几天。之后每行：
`消息ID|群|日 时:分|发言人: 内容`
- 本项目的群（消息 ID 的字母前缀就是群的 key；`groups` 字段写 label）：
{{groups}}
  一个项目可能有多个群（如核心小群 + 带家属的大群），按 label 区分。
- `⏎` 是换行；`（回复 X: …）` 是引用回复（X 已统一成显示名）；`[图片] [语音] [表情] [文章] 标题 [链接] …` 是非文字占位，`[图片] 配文` 后面的字是发图的人自己写的。
- 发言人 `me` 是网页作者本人（显示名 `{{me}}`）。

## 硬约束（任何模式都生效，优先于下面所有规则）

- **性别与关系以此为准**（写代词、关系时不许凭昵称推断，反串称呼照叫不点破）：
{{gender_table}}
关系：{{relations}}
1. **用户点名的禁区**：以下话题不收、不在任何字段里提（连概括也不写）：
{{taboo_extra}}
2. **本群敏感词**：事件的标题、摘要、月概括里不出现这些词（构建时隐私闸门会提醒）：
{{sensitive_words}}
3. **真名**：只用群昵称/显示名，不写以下真名：
{{real_names}}
4. **公开细节档位 `{{public_detail}}`**：
   - standard（缺省）：可以收这件事，但**不写具体细节**——具体金额（“28k”“3 万”“¥500”）、住址/小区/门牌、证件与账号、健康诊断细节（病名、检查结果）、他人隐私。写成概括：“拿到了 offer”“去看了医生”“搬了新家”。
   - full（只有用户明确选过才会是 full）：照实记录，金额、病情等可以写。

## 选什么（不设数量上限）
**凡是多人参与讨论、或和群里的人有关系、或值得纪念的事，都要收**，有多少收多少：
- 人生节点：恋爱、结婚、订婚、宝宝、买房装修搬家、换工作/升职/离职/毕业、考试、宠物、生病住院等
- 聚会、出行、约饭约球约牌局、一起玩游戏/看剧、组局
- 多人热议的话题（同一话题有多人来回讨论就算）
- 名场面/群梗：金句、离谱的事、反复被提起的梗、互相调侃
- 个人分享但引发多人回应的也算

不收：一个人自言自语没人接、单纯转发没人讨论。
{{scale_rules}}

## 什么算「同一件事」（照此执行，不要自己另定规则）
- **算一件**：同一场活动（从约、到去、到晒照）；或同一话题的连续讨论（中间断开不超过约 3 天）。合成一条，refs 从这一段里挑。
- **各算一件**：隔几天、隔周又重演的群梗，又吵了一次的老话题，又一次组局。每一次都单独成一条事件，summary 里写明“又一次”（例如“大家又一次拿那句老梗接龙”），**不要**把一个月里的多次出现合成一条、refs 跨一整月。
- 拿不准时：refs 能不能都落在 3 天之内？不能，就拆开。
为什么不设上限：下一步合并只去重、不删减；删减留给用户在成品上做。抽取阶段漏掉的事后面补不回来，多收的随时能删。

语气客观、轻松，像群里的老朋友写的编年史。

## 隐私开关 `{{family_safe}}`

**off（默认，只给群内成员看）**：不做下面这几类分寸过滤（感情、工作挫折、八卦可以收）。上面的「硬约束」照旧生效——用户点名的禁区、敏感词、真名在任何模式下都不写，具体细节按 `{{public_detail}}` 处理。

**on（成品会给所有人的伴侣/家属看，或某段时期还没有家属在群里但成品要给家属看）**——以下**额外不收**：
1. 恋爱、暧昧、表白、相亲、前任、单身调侃、谁喜欢谁。这些在当年可能是群里日常，但如今伴侣看到会尴尬。
   唯一例外：本人官宣的订婚/结婚/领证/婚礼，可以收，写得喜庆就好。
2. 吐槽工作/领导/同事、考试失利、找工作被拒等挫折。除非最终是好消息——那就只写好消息。

开关 on 时也不设数量上限，只是这几类不收。

## 输出
每个分段文件写一个合法 JSON（不加注释）：
- 文件头是「第 1/1 段」（整月只有一段）→ 直接写 `{{project}}/work/events/<月份>.json`
- 否则 → 写 `{{project}}/work/part_events/<分段文件名去掉.txt>.json`，`month_summary` 写本段概括，之后由合并任务去重

```json
{"month":"YYYY-MM","month_summary":"本段概括（≤30字）","events":[
 {"date":"YYYY-MM-DD","title":"≤14字","summary":"≤80字，说清谁、发生了什么、大家什么反应",
  "people":["显示名"],"category":"人生节点|聚会出行|群内热议|名场面","heat":1,
  "refs":["A1234","B56"],"groups":["群 label"]}]}
```
- `heat`：3=全群沸腾/重要人生大事，2=多人热议，1=值得一记
- `title` ≤14 字，`summary` ≤80 字，`month_summary` ≤30 字（超了会被机检报出来）
- `refs`：2–6 条最能代表这件事的消息ID，**必须真实存在于该文件**，按时间排序
- `date`：**等于 refs 里最早一条消息的日期**（不早于、也不晚于）
- `people`：用聊天里的显示名；作者本人写 `{{me}}`
- `groups`：事件发生在哪个（些）群
- 同一件事的界定见上文「什么算同一件事」；明显跨段的事也照常写，后面会合并去重
- **交稿前自检**（与主控 check 阶段同一个脚本、同一口径，不要自己另写检查脚本）：
  `{{check_cmd}}`
  查 refs 数量与存在、date、长度、people、refs 跨度、代词与性别。按警告改到“未处理 0 条”再回报；你认为确属合理、不该改的（如两头各只有一条消息、拆开反而说不清的跨度），不要硬拆，在回报里写明事件和理由，由主控决定是否标记保留

完成后每个文件回报一行：`<文件名>: N 条（共 M 行，已读完）`，M 是文件总行数；没读完就写 `<文件名>: N 条（读到第 X 行/共 M 行）`。多个文件用分号隔开。
