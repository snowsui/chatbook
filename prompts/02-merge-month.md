> 用途：把同一个月被切成多段分别抽出的事件合并成一个月文件｜何时用：01 抽取完成后，对有多段的月份逐月执行｜输入：`{{project}}/work/part_events/<月份>_p<i>.json`（分配给你的月份 `{{months}}`）｜输出：`{{project}}/work/events/<月份>.json`

# 分段合并规则（只去重，不删减）

同一个月被切成多段分别抽了事件。把同月各段合并为一个文件。

- 只读 `work/part_events/` 下该月的 JSON，**不需要读聊天原文**。
- **只合并真正重复的事件**：同一件事因为跨段（或跨天）被拆成两条以上 → 合并为一条：
  - `date` 取最早
  - `summary` 重写（≤80 字），覆盖各条的信息
  - `people`、`groups` 取并集
  - `heat` 取最高
  - `refs` 从各条里挑 2–6 条，**只能用已有 ID**，按时间排序
- **不是重复的一律保留，不删减、不挑选、不改写**（直接原样拷贝）。
  为什么：抽取阶段刻意“宁多勿漏”，合并阶段再挑选就等于第二次过滤，而合并员没读原文，没有资格判断什么不重要。删减由用户在成品上做。
- “相似”不等于“重复”。「同一件事」的界定与抽取规则（prompts/01）一致：同一场活动、或同一话题的连续讨论（中间断开不超过约 3 天）才算一件；隔几天/隔周重演的群梗、月初月底各吵一次，是各自独立的事件（summary 里写“又一次”的那种），**不要合并**。拿不准就保留两条。
- `month_summary` 根据全月重写（≤30 字）。
- `events` 按 `date` 排序（同一天保持原来的先后）。
- 格式与各段一致：合法 JSON、UTF-8、不转义中文（`ensure_ascii=False`）、缩进 1 格；每个事件的字段顺序为 date, title, summary, people, category, heat, refs, groups。
- **交稿前自检**（与主控 check 阶段同一个脚本、同一口径）：`{{check_cmd}}`，按警告改到“未处理 0 条”再回报；确属合理的例外在回报里写明事件和理由。

完成后只回复一行：每个月份 `<月份>: 合并前 N → 合并后 M`，分号隔开。
