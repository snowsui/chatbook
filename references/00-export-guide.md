# ⓪ 导出指南：怎么把聊天记录交给这个 skill

本 skill 不负责获取聊天记录；请使用平台官方导出功能，或自行选择工具导出为下列任一格式，并确保只处理自己有权处理的记录。

## 支持的格式（全仓库只在这里列一次）

| format | 是什么 | 备注 |
|---|---|---|
| `json-array` | 通用 JSON 数组，每条一个对象：`time`（或 `timestamp` 秒）、`sender`、`content`，可选 `sender_id`、`msg_id`、`type`（text / reply / image / sticker / voice / video / link / article / file / system…）、`is_self`、`title`、`reply_to`（被回复消息的 msg_id，或 `{msg_id, sender, sender_id, content}`） | 自己写脚本整理、或别的工具导出时最方便的目标格式；带上 msg_id、sender_id、reply_to 信息就最全。样例 `assets/samples/array.json` |
| `chatlab` | ChatLab 开放格式（chatlab/meta/members/messages） | 有消息 ID、账号、引用关系 |
| `telegram` | Telegram Desktop 导出的 result.json | 有消息 ID、账号、引用关系 |
| `qq` | QQ 消息管理器导出的 txt | 有 QQ 号，没有消息 ID |
| `txt` | 纯文本，几种常见行格式（见下） | 没有账号和消息 ID |
| `csv` | 表格，至少有 时间 / 发送者 / 内容 三列 | 可以有消息 ID 列 |

字段细节见 `scripts/ingest.py` 开头的说明。文本不是 UTF-8 也行：导入时会依次试 GB18030、UTF-16，并提示按哪种读的；都认不出会给一条 `iconv` 转码命令。

## QQ：消息管理器导出 txt

QQ 电脑端自带“消息管理器”，可以把一个群或好友的记录导出成 txt：

1. 打开消息管理器（主界面菜单或聊天窗口的“消息记录”入口里）；
2. 在左侧列表找到要导出的群，右键 →“导出消息记录”；
3. 保存类型选 **txt**，保存。

菜单位置以你使用的版本为准；不同版本的入口名字和位置可能不一样，有的版本没有这个功能。导出的 txt 开头有 `消息对象:` 一行，每条消息是 `2019-01-01 12:00:00 昵称(QQ号)` 下一行起是内容，init_project 会自动认成 `qq`。

## Telegram：Telegram Desktop → Export chat history → JSON

1. 用 Telegram Desktop（电脑端）打开那个群；
2. 右上角 ⋮ 菜单 → **Export chat history**；
3. 照片、视频等媒体可以都不勾（文字产出用不到，导出也快）；格式选 **Machine-readable JSON**；
4. 导出完成后，目录里的 `result.json` 就是要给 skill 的文件。

## 微信：合并转发，复制成 txt

微信没有官方的聊天记录导出功能，手动整理成 txt：手机上长按一条消息 →“多选”→ 勾选一段 →“合并转发”给“文件传输助手”；在电脑上打开这条“聊天记录”，全选复制，粘贴进一个 txt 文件。一次能勾的条数有限，长记录要分多段转发，几段可以粘进同一个文件，也可以各存一个文件一起给。

粘出来的文本常见这几种样子，`txt` 格式都能读：

```
张三 2024/1/1 12:00          ← 昵称 + 日期时间，下一行起是内容（秒可有可无，日期也可以写 2024-01-01）
新年快乐

[2024-01-01 12:00] 张三：内容  ← 时间、昵称、内容在一行

2024-01-01                    ← 没有时间的形态：一行日期，下面每行「昵称：内容」
张三：新年快乐
李四：同乐
```

没有时间的形态：整份文件一行带时间的都没有时，按「昵称：内容」读。日期取文件里单独一行的日期（`2024-01-01`、`2024/1/1`、`2024年1月1日`，后面的消息都算这一天，直到下一个日期行）；文件里没有日期行时，导入时写成 `文件:txt@2024-01-01`（或在 config 的这个群里写 `"date": "2024-01-01"`）。两者都没有，这份文件不导入，init_project 会说明怎么补。每天的消息按文件顺序从 00:00:00 起每条加 1 秒。

手动方式会丢掉的东西（开工前告诉用户）：

- **时间精度**：最多到分钟；没有时间的形态只剩日期，钟点是假的——这种群会被标成“没有真实时刻”，数据页的热力图、夜猫子、早鸟、活跃时段、回复时延自动不算它（页面脚注写明）；同一个群的几份无时间记录也没法按时间重叠去重（自己先删掉重复的段落）。
- **引用回复**：引用的是哪条消息、引用谁，通常只剩文字或直接没有；人物名单的“被引用回复”统计、引用矩阵会偏少或为空。
- **消息类型**：图片、语音、表情、文件、红包等变成占位文字或直接消失；撤回、系统提示不一定在。
- **账号**：只有显示出来的名字（可能是你给对方的备注名），没有账号，同一个人改过名要在人物名单那一步手动合并。
- **作者本人**：你自己的消息显示的是你的昵称，要在人物名单那一步告诉 skill 哪个是你。

## 通用：任何能导出成上面格式的工具

只要最后是 txt（上面的常见行格式）、csv（时间 / 发送者 / 内容 三列，列名不同也能认出常见的中英文列名）、json-array 或 ChatLab 开放格式，就能用。识别不了的文件，init_project 会让你写成 `文件:格式` 指定。

## 多份文件怎么给

一次全给就行，不用先挑：

- 给一个文件夹（递归找 .json / .txt / .csv），或者列出好几个文件路径，也可以混着给；
- 可以是几个不同的群，也可以是同一个群导出过好几次（换手机前后、隔一段时间又导出一次）——时间重叠的部分按消息 ID 去重，没有 ID 的按 时间+发送者+内容 去重；
- 格式可以混用：一个群是 json、另一个是 txt 都没问题。**同一个群**一份 json、一份手动 txt（格式不同）时，init_project 按“时间 + 内容”比对，重合够多会提示“疑似同一个群”和合并命令 `--same B=A`；确认后合并，重叠部分按 分钟+内容 去重。
- 一份文件读不了（空文件、只有表头、没有日期的 txt）不影响别的文件：能读的先导入，最后列出没导入的文件和修复办法。整个群不要了：`init_project.py --project <dir> --drop-group <key>`。

```
python3 <skill>/scripts/init_project.py --project <dir> ~/exports/ ~/Downloads/old.txt [怪文件.log:txt]
```

init_project 一次读入：识别格式、分群、合并同一个群的多次导出、写最小 config、跑 ingest。之后按 references/01-ingest.md 的「多份记录与人物名单」做人物名单。
