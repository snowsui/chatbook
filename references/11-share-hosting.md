# ⑪ 分享形态与托管选型

成品不一定要上线。先想清楚**给谁看、在哪看、泄露了有多糟**，再挑形态和托管方式。

## 分享形态（三个脚本）

| 脚本 | 产出 | 适合 |
|---|---|---|
| `build_share_cards.py` | `out/cards/<人>.png/.html` 每人一张 1080×1920 竖卡 + `_group` 群体总卡 | 发群里、发朋友圈的"一图流" |
| `build_wrapped.py --year 2023` | `out/wrapped-2023.html` 年度报告，全屏翻页（点右边/左滑下一页，点左边/右滑上一页，方向键也行） | 年末发群里，手机上一页页翻 |
| `build_locked.py --page people.html` | `out/locked/people.html` 输入口令才显示的页面 | **仅用于免费静态托管**（GitHub Pages / Vercel / Netlify，无服务器、做不了登录）：给公开链接加访问口令 |

- 卡片的数据：发言量、最活跃时段、最常一起聊的人来自 `work/stats/<人>.md`（先跑 person_stats.py）；口头禅 TOP3 从 all.json 现算（规则见下）；总卡的发言量来自 `work/metrics.md`（没有就直接从 all.json 数）；品藻取人物志第二行 `> …`。
- **代表性原话会核对**：取人物志里第一句「…」引语（不同的字少于 4 个的往后排），必须能在此人自己的某条消息里找到（忽略换行），找不到就不放。想手选，写 `config.pages.share.quote = {"张三": "原话"}`，同样要核对得上。
- **口头禅规则**（卡片与年度报告相同，sharekit.catchphrases）：≤8 字、在 ≥3 个不同月份出现、共被用 ≥5 次的短句；纯笑声/纯表情不算（单列"最爱的笑法"：最常用的那种笑声，≥5 次），问句不算（"几点到？"这类一次性问句不是口头禅）。年度报告只看本年的消息，所以宁缺毋滥：不够格就不显示。
- 卡片与年度报告写文件前过隐私闸门（见 09-privacy.md）；人物志里的引语出处标注 `<!--k:…-->` 读取时去掉。
- 年度报告只用统计与 stable/ 事件。`show_chat_groups` 允许的群，名场面下面会附该成员的最多 2 句原话——**允许原文前先想清楚这个页面会转到哪**。
- 每人的名场面尽量不重复：没被别人用过的优先，其次 TA 是事件主角（people 第一位）、人少的。
- PNG 需要 Python 版 Playwright：`pip install playwright && python3 -m playwright install chromium`（装了系统 Chrome 时可以省掉第二步，脚本会退到 `channel=chrome`）。没装就只出 HTML，HTML 在手机上按屏宽等比缩放，长按截图一样能用。

## 公开链接加访问口令（build_locked.py）

**定位**：本地单文件默认不加密，直接发、发给谁由用户自己决定。`build_locked.py` 只在一种情况下用：页面要放到**免费静态托管**（无服务器、没法做登录），链接是公开的，需要给它加一道访问口令。要长期在线、内容多，直接用方案 D 登录版。

加密前先过隐私闸门：按 site 口径扫已生成的公开页面及其输入，再把 `--page` 的每个页面和口令页的标题、提示语按重点类规则（已删除素材、敏感词、引用 personas/）查一遍，列出疑似问题供你过目，默认只提醒、开 `privacy.strict` 才拦（09-privacy.md 第二节）。口令从环境变量 `CHRONICLE_LOCK_PASS` 读，没有就在终端里输两遍，不写进任何文件。

做法：整页用 AES-256-GCM 加密，加密用的 key 由口令经 PBKDF2-HMAC-SHA256(口令, 随机盐, 默认 60 万次，最少 20 万次) 派生，浏览器用 WebCrypto 还原后 `document.write` 出原页。加密靠 `cryptography` 包（`pip install cryptography`），不自己实现算法。

### 安全边界（必须告诉用户）

- **防的**：公开链接被转出去，不知道口令的人点开只看到一个口令框；搜索引擎、链接预览、网盘扫描看不到内容。
- **不防的**：拿到文件的人可以离线无限次猜口令。60 万次 PBKDF2 让每次猜测变慢，但**弱口令（生日、群名、手机号、6 位数字）几分钟到几小时就能被试出来**。口令要长：建议 ≥12 位、几个不相干的词连起来（如 `火锅-302-冬至-喵`）。脚本拒绝 <8 位，<12 位会提醒。
- 口令另走渠道（当面说、私聊），别和文件发在同一条消息里。口令一旦发进群，就等于公开给了能看到这条消息的所有人，包括以后进群的人。
- 解开以后就是原页面：对方可以截图、另存，加密管不了。真正不能外传的内容，不要做进任何页面。
- 口令页的标题、提示语是明文（`--title`、`--hint`），别写敏感内容。缺省标题"需要口令"。
- 需要 WebCrypto：本地直接打开文件、或 https 地址都可以；**纯 http 地址、个别 App 内置浏览器打不开**（页面会提示改用浏览器）。微信里点开 html 文件的行为因版本而异（以当前版本为准），稳妥做法是让对方"用浏览器打开"。
- 换口令 = 重新跑一次脚本；旧文件已经发出去的，用旧口令照样能开。
- 多个页面一起加密时，页面里"大事记 / 人物志"之类的栏目链接会指向 `locked/` 下的同名文件，每个页面都要单独输一次口令。

## 托管方案

### A. 直接发文件（单文件 HTML / PNG 卡片）
零成本、不需要域名和账号。单文件大事记、人物志、年度报告都能直接发，默认不加密，发给谁由用户自己决定；内嵌字体后可能几 MB，聊天软件传文件有上限（以当前版本为准）。PNG 卡片最省心，谁都能看。

### B. GitHub Pages
- 免费账号只能从**公开仓库**发布 Pages；私有仓库发布 Pages 需要付费计划（Pro / Team / Enterprise）。**即使仓库私有，发布出来的站点本身默认也是公开可访问的**；只有 GitHub Enterprise Cloud 支持限制站点访问者（以官方当前条款为准）。
- 所以：要放 GitHub Pages，就**只放加了口令的页面**（`out/locked/*.html`），仓库里不要放 out/ 原文件、work/、聊天导出。公开仓库里的口令页任何人都能下载去离线猜口令，口令更要长。
- 有容量与流量的软上限（站点 1 GB 量级、每月 100 GB 带宽量级，以官方当前条款为准），对年鉴绰绰有余。

### C. Vercel / Netlify 静态托管 + 密码
- 两家都能免费托管静态文件，但**平台自带的"访问密码"基本都是付费功能**：
  - Vercel：部署的 Password Protection 属于付费附加项/高级计划功能（以官方当前条款为准）；免费的 Hobby 计划限非商业使用。另有要求访客登录 Vercel 账号的部署保护，不适合给群友用（以官方当前条款为准）。
  - Netlify：站点级密码保护（Visitor access / 基础认证）需付费计划（以官方当前条款为准）。
- 不想付费：在这两家上**托管加了口令的页面**，效果等同 B，只是换了个托管地址（https，WebCrypto 可用）。
- 也可以自己在 Edge Function / Middleware 里写 Basic Auth，但那就和 D 是同一类工作量了，不如直接用 D。

### D. Cloudflare Worker 登录版（见 07-publish.md）
- 服务端校验账号密码（HMAC 签名 cookie），未登录拿不到任何数据和资源——**没有可离线暴力破解的文件**，这是它比口令页强的地方。
- 需要 Cloudflare 账号；要自定义域名就需要域名（也可以用 `*.workers.dev` 子域，个别访客网络可能访问不了，以实际测试为准）。Workers 免费额度对一个群的访问量足够（每天请求数上限以官方为准）。
- 内容最全：按月懒加载、搜索、年度十大、最多四个栏目（大事记/小剧场/人物志/数据，有哪个页面出哪个）。
- 打包时隐私闸门会列出疑似问题供你过目，默认只提醒、开 `privacy.strict` 才拦（09-privacy.md 第二节）；想让被写的人先看看，可以用本人确认页（可选，references/09-privacy.md 第四节）。
- 也可以用 Cloudflare Access（Zero Trust）给站点加邮箱验证码登录，小团队有免费档（人数上限以官方当前条款为准），适合不想共享一个密码的场合。

## 选型表

| 方案 | 要域名？ | 要账号？ | 隐私强度 | 成本 | 适合谁 |
|---|---|---|---|---|---|
| A. 直接发单文件 / PNG | 否 | 否 | 低：谁拿到谁能看 | 0 | 只在原群里传、内容本来就不敏感 |
| B. GitHub Pages + 口令页 | 否（有 github.io 子域） | GitHub | 中（同上；文件公开可下载） | 0（公开仓库） | 想要一个固定网址、会用 git |
| C. Vercel / Netlify + 口令页 | 否（有平台子域） | 平台账号 | 中（同上） | 0 | 同上，习惯这两家 |
| C. Vercel / Netlify 平台密码 | 否 | 平台账号 | 中高：服务端拦截 | 付费（以官方当前条款为准） | 已经在付费用这两家 |
| D. Cloudflare Worker 登录版 | 可选（推荐自有域名） | Cloudflare | 高：服务端鉴权，无可离线破解的文件 | 0（免费额度内） | 要长期在线、要搜索和全部栏目 |

建议的默认：**卡片 PNG 发群 + 年度报告/人物志直接发单文件**（发给谁由用户定）；想要一个固定网址又不想用服务器，就用免费静态托管 + 口令页；要长期在线、内容多、群友多，就上 D。

## 验收（交付前）

1. `scripts/test_share.sh <项目目录> [年份]`：无交互部分（卡片/年度报告生成、原文不外泄、加密往返、错口令解不开、短口令与低迭代被拒）。
2. 浏览器（或 Playwright）：390px 宽打开卡片、年度报告逐页翻、口令页输错口令提示"口令不对"、输对后显示原页面；三者都无横向滚动。
3. 口令页文件里搜一下正文里的人名，确认不是明文。
