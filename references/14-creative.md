# 用人物模型写群聊戏 + 检验“像不像”

人物模型（⑤）的第二个用途是创作。最常见的创作需求是“让这几个人在某个情境里聊一段”。这一节给出一条可复用的流水线：**抽节拍表 → 按节拍表写 → 和真实片段盲测**。

## 为什么要按比例抽样，而不是“让写手自由发挥”

- 真实项目的全量统计：每个人有 35–48% 的发言和上文 4 条没有共同字词（跳线、讲自己的事），单条发言占五到七成，一成多的开头两小时内没人接。群聊是多线并行的。
- 人物模型最初只写“这个人默认怎么接话”，盲测命中率卡在 35–70%；把“默认接法”调来调去只会来回过冲（lessons.md 第 16–18 条）。定稿模型改成给**分布**（0.6 节发言类型分布 + 私人频道 + 第 7 节多分支概率）。
- 分布要用起来就得抽样。写手凭感觉“按比例”写，几乎一定写成一个话题、人人认真接一句、最后有结论——这是写作的本能，也是最容易被看穿的地方。所以把“比例”交给脚本、把“声音”交给写手：
  - 脚本决定：谁说（按“谁接谁”的真实次数）、哪一类（按本人的类型分布）、单条还是连发（按单条占比）、哪里冷场（按本人发言后冷场的比例）、哪里开新线、哪条线落空、被点名的人接不接（按真实的“被点名后接话率”）。
  - 写手决定：每一句具体说什么——用人物模型第 4 节的声音、0.6 节的私人频道、第 5 节的关系、第 8 节的禁区。

## 流程

```
S=<skill>/scripts
# 0. 统计（建模时已有就跳过）
python3 $S/turnmix.py --project <dir>
python3 $S/metrics.py --project <dir>
# 1. 节拍表（可多抽几张挑一张；同一 seed 结果固定）
python3 $S/scene_sampler.py --project <dir> --people 阿杰,小鹿,老周 --turns 40 --seed 3 --situation "小鹿想组织五一短途旅行"
#    → work/scenes/beats-s3.md（给写手）+ beats-s3.json
# 2. 写戏（强模型子任务）
python3 $S/fill_prompt.py --project <dir> --prompt 18 --set tag=s3 --out work/prompts/18-s3.md
#    → work/scenes/scene-s3.md（只有聊天行）+ scene-s3-notes.md（偏离说明）
```

只为创作，到第 2 步为止。要检验像不像，接着做第 3–5 步：

```
# 3. 真实对照片段：同一批出场人、同样 turn 数；--count 多截几段，-1 做对照，其余给评审当“熟悉材料”
python3 $S/scene_sampler.py --project <dir> --real --people 阿杰,小鹿,老周 --turns 40 --seed 3 --count 4 --tag r3
# 4. 打乱成 A/B，派不知情的评审（每组一个新子任务）
python3 $S/scene_sampler.py --project <dir> --pack work/scenes/scene-s3.md work/scenes/real-r3-1.md --id b1
python3 $S/fill_prompt.py --project <dir> --prompt 19 --set blind_id=b1 ref_tag=r3 --out work/prompts/19-b1.md
# 5. 汇总
python3 $S/scene_sampler.py --project <dir> --tally      # → work/scenes/blind/summary.md
```

注意：
- `fill_prompt.py --set` 一次写多个键值（`--set a=1 b=2`），不要写两次 `--set`（后一个会覆盖前一个）。
- 每组都换**新的节拍表 seed、新写手、新真实片段、新评审**。评审看过一组答案就不再“不知情”。
- 写手不能读 `work/scenes/real-*`、`blind/`、`all.json`（prompts/18 已写明）；评审不能读人物模型、节拍表、生成稿和答案（prompts/19 已写明）。
- 出场人是全体成员的子集时，`--real` 可能找不到全由这几个人组成的连续片段，会退而取“出场人占比最高”的一段并提示——这时对照片段里会混进别的成员，盲测会偏。人少的群直接用全体成员做盲测更干净。
- `--real` 把日期换成“第 N 天”（跳过的日子不计）、正文里的年月日换成“某日”、换行合成一行；`--pack` 只保留聊天行和“第 N 天”分隔行，两段格式一致。

## 节拍表长什么样（示意：虚构测试群，非真实数据）

```
| # | 时刻 | 发言人 | 类型 | 条数 | 线 | 接谁 | 备注 |
| 1 | 21:49 | 老周 | 开头·讲自己的事（含“我”） | 1 | 1 | — |  |
| 2 | 21:50 | 阿杰 | 只发图/语音（可配一句） | 2 | 1 | 老周 |  |
| 3 | 21:51 | 老周 | 短评 ≤15 字 | 1 | 1 | 阿杰 |  |
| … |
| 12 | 21:57 | 小鹿 | 跳线：说自己那条线的事，与上文无共同字词 | 1 | 2 | — |  |
| 13 | 21:58 | 阿杰 | 短评 ≤15 字 | 1 | 2 | 小鹿 |  |
| 14 | 22:00 | 大熊 | 纯反应：哈哈/表情/附和 | 1 | 2 | 阿杰 | 之后冷场（>2 小时没人说话） |
|   | 第 2 天 | … |
```
表头还有各人的类型分布、单条占比、冷场率（来源：`work/turns/<人>.md`，或人物模型 0.6 节的本人一行——有模型时以模型为准），以及“线”列表（谁开的、话题、包含哪些 turn）。

抽样规则（详见脚本顶部说明）：
- 下一位发言人：P(B | 上一位 A) ∝ B 接 A 的真实次数 + 平滑；上一 turn 点名了某人时，按真实的“被点名后接话率”让被点名者接。
- 冷场后的开头：按各人“冷场后开话题”的次数抽；开头不会是纯反应或跳线。
- 线：开头、跳线、转链接开新线；纯反应和开头后的第一句接上一句；其余七成接上一 turn 的线、三成回到本轮另一条线（0.7 是经验值）；冷场之后旧线不再续。只有一个 turn 的线标“落空”。
- 时刻按真实的 turn 间隔抽，只是建议值。

## 怎么评估、怎么解读

**主指标：被识破率** = 评审认对“哪段是真的”的比例。
- **接近 50% 最好**：评审分不出来。明显低于 50%（评审反而把生成的当真）也不是好事，常见原因是生成稿抄了原句、或真实片段太“散”而生成稿更像评审心目中的群聊——看破绽归类再判断。
- **组数**：2 组只有 0/50/100% 三种结果，只能看方向；要说“分不出来”，至少 10 组、识破率落在 30–70%（10 组的随机波动约 ±15%）。
- **把握**：识破且把握 4–5 的组最有信息量，优先读它们的破绽。

**副指标：逐人像不像**（1–5，评审对 A/B 两段里每个人分别打分）。`--tally` 给出每人在生成片段与真实片段里的均分和差。差值越接近 0 越好；某人持续低 1 分以上，回去看这个人的人物模型第 4 节和 0.6 节。真实片段的分数本身就是“评审基线”：真实片段也只拿 3.5 分的人，说明熟悉材料里这个人出场太少。

**最有用的是破绽归类**（prompts/19 的六类：节奏 / 长度与形态 / 声音 / 话题 / 关系 / 格式）。按类别计数，对症处理：
- 节奏类（太连贯、没冷场、话题收得整齐）多 → 写手没照节拍表写，或偏离太多：检查 notes 的偏离说明；必要时在 18 里收紧。
- 长度与形态类多 → 写手没按 metrics 的长度中位数和标点习惯写；把“长度中位数”写进节拍表表头或 18。
- 声音类集中在某个人 → 那个人的人物模型第 4 节不够用（句式模板、口头禅、称呼）。这是回修人物模型的有效线索，但同样遵守“只采纳与全量统计一致的建议”（06-validation.md）。
- 话题类多 → 私人频道写得太少或太泛（0.6 节）。
- 格式类 → 流水线漏洞（时间、引用回复、占位符写法不一致），修脚本或 18，不算模型问题。
- 也读评审写的“真实那段里也像假的地方”：它告诉你真实群聊有多不完美，写手可以更放松。

**这套盲测测什么、不测什么**：它测“读过几段真实聊天的人能不能分辨”，不测“本人或老群友能不能分辨”。子任务评审只看过几十个 turn，比真群友好骗得多；条件允许时请用户自己（或群友）做几组盲测，那是最硬的标准。

## 给用户的提醒

- 生成的群聊是**虚构创作**，不能当成“某人会这么说”的证据，更不要发回群里冒充聊天记录。
- 群聊戏会让人物“说话”，禁区比人物模型更容易踩：写手按人物模型第 8 节写作禁区 + config.taboo_extra；要给别人看的成品，按 lessons.md 第 7 条的公开口径再收一遍，小剧场（③）的化名规则同样适用。
